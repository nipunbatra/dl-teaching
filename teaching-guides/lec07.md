# Lecture 7 · CNN Deep Dive & Classic Architectures · Teaching Guide
*First-time-instructor companion. Audience: undergrads, one ML course.*

## The spine (say this in 2 sentences)
A convolution is just a **shared, sparse linear layer** — and that one architectural choice buys three things at once: orders-of-magnitude fewer parameters (weight sharing), translation **equivariance** (the same detector runs everywhere), and a receptive field that **grows with depth** so the network composes edges → parts → objects. CNNs win on images not because they're bigger but because images actually obey those symmetries, so the "missing" capacity relative to an MLP was capacity we never needed.

## 80-minute plan
- ⭐ **Core (~45 min):** the parameter-blowout pop-quiz (FC vision layer ≈ 6×10⁸ params vs a 3×3×3×64 conv ≈ 1,792) · the **output-size formula derived** ($O=\lfloor(W-K+2P)/S\rfloor+1$) with the lawnmower analogy · the worked numerics (VGG first layer 224→224 "same" padding; ImageNet stem 224→112) · **equivariance vs invariance** (conv is equivariant, pooling adds local invariance) · **receptive field grows with depth** and the RF recursion · **why stack 3×3** (three 3×3 = one 7×7's RF, ~45% fewer params, 3 ReLUs not 1). Every student must leave able to compute output size by hand and explain why a 3×3 stack beats a 7×7.
- ⭐⭐ **Should-cover (~25 min):** max-pool worked numeric · the **three inductive biases** (locality, translation equivariance, hierarchy) and *why each is correct for images* · the 350,000× MLP-vs-CNN parameter count · **1×1 conv** as channel mixing / bottleneck (the RGB recipe numeric) · the classic timeline (LeNet → AlexNet → VGG → GoogLeNet) and the one-line contribution of each.
- ⭐⭐⭐ **Optional / skip-if-tight:** the **effective** receptive field (Gaussian-shaped, Luo 2016) · the dominoes/chain-reaction RF framing · feature-visualization table (Zeiler-Fergus) · the data-efficiency CNN-vs-ViT plot · dilation. Gist if asked about effective RF: "the *theoretical* RF grows linearly with depth, but in practice center pixels dominate (it's Gaussian-shaped), so the real RF is smaller than the formula says — which is why later architectures add dilation or attention to actually reach global context."
- **Do live on the board:** the **stacked-3×3 vs one-7×7 comparison** end to end. Trace RF: conv1 → 3, conv2 → 5, conv3 → 7 (each layer adds $K-1=2$). Then params at $C=256$: one 7×7 = $49C^2 = 3{,}211{,}264$; three 3×3 = $27C^2 = 1{,}769{,}472$ — ~1.45M saved *per block*, plus 2 extra non-linearities. This is the single design decision that defines VGG and it makes both the RF recursion and the parameter argument concrete in one shot.

## Teach it like this
Open with the pop-quiz blowout: an FC layer from a 224×224×3 image to 4096 units is ~6×10⁸ params; one small conv is ~1,792 — *a factor of 350,000* — so "where did the capacity go, and did we lose representational power?" Hold the answer. Build the output-size formula from the lawnmower picture so every term has a meaning (not a memorized box), then make the equivariance/invariance distinction crisp with the "two cat-detector robots" image (the equivariant robot's laser tracks the cat; the invariant robot just yells CAT). Receptive field is the engine of the lecture: it grows with depth, which is *why* stacking small kernels works — pay off with the 3×3-vs-7×7 board derivation. Close by answering the pop-quiz: the missing capacity was never needed — equivariance + locality mean an FC layer would *want* to learn the same filter at every pixel, and conv bakes that constraint in for free (same idea as ridge in ES 335 — a constraint that matches the problem shrinks the search space, not the true capacity).

## Heads-up for YOU (subtle points to get right)   ← most important section
- **Convolution is *equivariant*, not *invariant* — and pooling is what adds (a little) invariance.** Equivariant: shift the input 10px right and the feature map shifts 10px right (output *changes in step*). Invariant: shift the input and the output *doesn't change*. A single conv layer is equivariant; max-pool over a window gives *local* invariance; stacking many pool/stride layers compounds local invariance toward *global* invariance at the classifier head. If you call convolution "translation invariant" (a very common slip) a sharp student is right to object — the conv1 feature map visibly moves when the input moves.
- **The RF recursion has a stride *multiplier* — it's not just `+ (K−1)` per layer.** For stride-1 stacks, $\text{RF}_\ell = \text{RF}_{\ell-1} + (K-1)$. With strides, each layer's $(K-1)$ term is multiplied by the *product of all previous strides*: $\text{RF}_\ell = \text{RF}_{\ell-1} + (K-1)\prod_{i<\ell}S_i$. Stride is a *multiplier*, which is exactly why ResNet-50 reaches RF ≈ 500 with only ~50 layers. If you teach only "+2 per layer" you'll badly under-count RF for any real (strided) network.
- **Three 3×3 ≈ one 7×7 only in *receptive field* — they are NOT identical functions.** The stack is *strictly more expressive* (3 non-linearities vs 1) and *cheaper* ($27C^2$ vs $49C^2$, ~45% fewer params). Don't say "they're equivalent" — say "same field of view, more expressive, fewer parameters." And note the RF count assumes stride 1; with pooling in between, two 3×3 don't simply sum.
- **A 1×1 conv is not "useless because it sees one pixel" — it mixes *channels*.** It's a full linear layer applied independently at every spatial position: at each pixel, an $(C_\text{out}\times C_\text{in})$ matrix–vector product. It does *no spatial* mixing but *all channel* mixing — perfect for cheaply reducing/expanding depth (the bottleneck) without touching spatial structure. The attention output projection in a Transformer is literally a 1×1 conv on the channel axis.
- **"Same" padding means a specific formula, and only at stride 1.** "Same" output size needs $P=(K-1)/2$ *and* $S=1$. With stride 2 the output is roughly halved regardless of padding — "same padding" doesn't keep the size when you stride. Be precise or students will expect 224→224 from a stride-2 layer.
- **Pooling buys invariance for *classification* but throws away the localization you need for *detection/segmentation*.** "Where is the cat" should be invariant for a classifier (still a cat) but is exactly what a segmenter must recover. This is the seed for L09 — flag that the aggressive downsampling that helps classification is precisely what U-Net has to undo with skip connections.
- **"Deeper got worse" (pre-ResNet) was an *optimization* failure, not overfitting.** Past ~25 plain layers, *training* loss got worse — the model couldn't even fit the data. That rules out a generalization/capacity story and points at gradient flow / optimization, which is what ResNet's skip connections fix (next lecture). Don't let students file this under "too many parameters → overfit"; it's the opposite symptom.

## Where students stumble (and the fix)
- **Off-by-one in the output-size formula.** Symptom: a `size mismatch` RuntimeError at the FC head. Fix: hand-compute $O=\lfloor(W-K+2P)/S\rfloor+1$ layer by layer; the floor and the `+1` are the usual culprits. Have them do the VGG stem (224→112 with K=7,S=2,P=3) once on paper.
- **Confusing equivariance and invariance** (see Heads-up). Fix: the two-robot analogy plus the tiny max-pool example where the *same* `6` survives whether it's top-left or top-right of the window — that's local invariance; the conv map underneath still moved.
- **Believing 3 stacked 3×3 = 1 7×7 in every sense.** Fix: same RF, but emphasize *more non-linearities, fewer params* — and that this only holds at stride 1. Make them count both RF and params side by side.
- **Forgetting input normalization on a CNN.** Symptom: loss astronomically large at step 1, or stuck at chance. Fix: print `x.min(), x.max()` on one batch — pixels still in 0–255 means `Normalize` is missing; after normalization expect roughly ±2.
- **Putting a full-resolution FC head on a conv feature map.** Symptom: one layer holds ~99% of all parameters. Fix: print per-layer param counts; pool (or global-average-pool) *before* the head.

## If a student asks…
- **"Is convolution translation invariant?"** No — *equivariant*. Shift the input, the feature map shifts identically. *Invariance* (output unchanged under shift) is what the *classifier* wants, and we approach it by stacking pooling/strides on top of equivariant convs. Keep the two words distinct.
- **"Why 3×3 specifically — why not all 1×1 or all big kernels?"** 3×3 is the smallest kernel that still sees a center pixel *and* all 8 neighbors (captures orientation/edges); stacking them grows RF efficiently with extra non-linearities. All-1×1 does no spatial mixing; big kernels cost $K^2$ params for RF you can get more cheaply by going deeper. Modern default: 3×3 everywhere, 7×7 only at the stem.
- **"How big does the receptive field actually need to be?"** At least as large as the objects you care about — if the final RF is smaller than the object scale, the network literally can't see the whole thing and fails on off-center / large objects. Compute it with the strided recursion; this is a real debugging tool, not just theory.
- **"Effective vs theoretical receptive field?"** The formula gives the *theoretical* RF (linear in depth). The *effective* RF is Gaussian-shaped — center pixels contribute far more than the edges — so the practical RF is smaller. Consequence: very deep CNNs still struggle with truly global context, which motivates dilation and (later) attention.
- **"Why is a 1×1 conv ever useful?"** It mixes channels cheaply. Use it to squeeze 256→64 channels before an expensive 3×3 (the bottleneck), then expand back — same external shape, ~a quarter the compute. It's in GoogLeNet, ResNet bottlenecks, and Transformer FFN projections.
- **"If pooling throws away location, how do we ever do segmentation?"** You don't pool it all away — you keep the high-resolution encoder features and feed them back into the decoder via skip connections (U-Net, L09). Pooling is right for "what is it"; segmentation needs "where exactly," so the architecture has to recover the spatial detail.
- **"Why did plain very-deep nets get worse before ResNet?"** Optimization, not overfitting: *training* error rose with depth. Gradients/signal degraded through long chains of layers; ResNet's identity skip gives a clean path so adding layers can at worst no-op. (Full story next lecture.)

## If you're short on time
Cut: the effective-RF slide, the dominoes RF framing, feature-visualization table, the CNN-vs-ViT data-efficiency plot, dilation, and the long FAQ. Never cut: the **output-size formula derivation + one worked numeric**, the **equivariance vs invariance** distinction, the **RF-grows-with-depth recursion**, and the **3×3-stack-vs-7×7 board comparison** (RF *and* params). Those four carry every downstream lecture.

## Closing line
"A convolution is a linear layer that confesses its assumptions — locality, weight sharing, hierarchy written straight into the architecture — and it's worth ~350,000× fewer parameters than an MLP precisely because images actually obey those assumptions."
