# Lecture 9 · Detection & Segmentation · Teaching Guide
*First-time-instructor companion. Audience: undergrads, one ML course.*

## The spine (say this in 2 sentences)
Detection is just **classification + localization, repeated a variable number of times** — and three engineering ideas make that tractable: a **multi-task loss** (a `λ` trading class-error against box-error), an **anchor/grid** to pin the unknown object count to fixed predictors, and **NMS** to delete the duplicate boxes that result. Segmentation is the same probabilistic story pushed down to the pixel — the only thing that ever changes across this whole lecture is the *support* of the random variable (one label → one box → many boxes → one label per pixel).

## Where it sits
Builds on … L07–L08 (every detector/segmenter reuses a pretrained CNN backbone and just bolts on new heads; the freeze/fine-tune recipe carries over) · L00 (everything is still NLL: Categorical for classes, Normal/Smooth-L1 for boxes) · L07 (pooling buys classification invariance but *destroys* the localization that segmentation must now recover — the seed paid off here).
Sets up … L10 (the cliffhanger: images hold still, sequences don't) · L21–L22 (the U-Net encoder-decoder-with-skips is *the* diffusion-model backbone) · the open-vocabulary / CLIP thread (L17–L18) previewed at the end.

## 80-minute plan
- ⭐ **Core (~45 min):** the spectrum table (classification → localization → detection → semantic seg → instance seg, by *output type*) · the **multi-task loss** $\mathcal{L}=\mathcal{L}_\text{class}+\lambda\mathcal{L}_\text{box}$ with the two-section-exam analogy and the worked numeric · **IoU** (the worked example → 0.14) · **NMS** (the "stop the duplicate shouts" analogy + the step-by-step A/C/E example) · **one-stage vs two-stage** (R-CNN family proposes-then-classifies; YOLO does it in one grid pass). Every student must leave able to compute IoU by hand and run NMS by hand.
- ⭐⭐ **Should-cover (~25 min):** **mAP** (precision vs recall as a search-engine, AP = area under the PR curve, mAP@0.5 vs mAP@[0.5:0.95]) · **anchors + delta parameterization** (predict corrections relative to a fixed anchor, the directions analogy, the decode numeric) · **U-Net** (encoder-decoder with skip connections, the cheat-sheet analogy) · **Dice loss** for class-imbalanced masks (the 2×2 worked numeric) · the three segmentation flavors distinction (semantic vs instance).
- ⭐⭐⭐ **Optional / skip-if-tight:** the NMS pseudocode · **DETR** (set prediction + Hungarian matching, no NMS) · Mask R-CNN + RoIAlign · **SAM** (zero-shot, prompt-driven) · the open-vocabulary/CLIP shift · the detector speed/accuracy table. Gist if asked about DETR: "instead of predicting thousands of boxes then deleting duplicates with NMS, DETR predicts a *fixed set* of 100 and uses Hungarian matching to assign each ground-truth object to exactly one prediction — elegant, no NMS, but slower and data-hungry."
- **Do live on the board:** the **NMS step-by-step**. Five boxes for one car, scores A 0.95 / B 0.90 / C 0.80 / D 0.75 / E 0.70, IoU threshold 0.5. Pick A; IoU(A,B)=0.8 drop, IoU(A,C)=0.2 keep, IoU(A,D)=0.7 drop, IoU(A,E)=0.1 keep → pool [C,E]. Pick C; IoU(C,E)=0.15 keep → pool [E]. Pick E → done. `keep=[A,C,E]`, 5 boxes → 3 detections. Pair it with one IoU computation first so they see *exactly* what the threshold is comparing. This is the most-tested mechanic in the lecture and the one students get subtly wrong.

## Teach it like this
Open with the self-driving pop-quiz: a frame with 7 pedestrians and 3 cars — and ask "what *one property of this frame* breaks three of these options?" (the answer: the object count is *unknown and variable*). Walk the spectrum table top to bottom so students see detection as classification with two new problems — *where* (localization) and *how many* (variable count). The multi-task loss solves "where" (sum two losses, weight with `λ`); anchors/grid solve "how many" (fixed predictors everywhere); NMS cleans up the duplicates that creates. IoU and NMS are the mechanics — do both on the board. Then the one-stage/two-stage split is just "propose-then-classify (accurate, slow) vs one glance (fast, production)." Segmentation is the same story at the pixel; U-Net's skip connections exist precisely to undo the localization that pooling threw away in L07. Close on the revisited pop-quiz: only a variable-count detector (d) handles an unknown number of objects.

## Heads-up for YOU (subtle points to get right)   ← most important section
- **Box format is the #1 source of silent bugs — `(x,y,w,h)` vs `(x₁,y₁,x₂,y₂)` are NOT interchangeable.** The slides mix both deliberately (the cls+loc head outputs `(x,y,w,h)`; the IoU example uses corners `(x₁,y₁,x₂,y₂)`). IoU math only works on *corner* format. If a student computes IoU treating `w,h` as `x₂,y₂`, every number is wrong and the loss falls while mAP stays ≈0. State the format every time you write a box, and convert explicitly.
- **NMS is *greedy and per-class* — and it can suppress true positives.** It sorts by confidence, keeps the top box, deletes everything overlapping it above threshold, repeats. Two consequences to say out loud: (1) it's run *per class* (a dog box never suppresses a cat box); (2) if two *different* real objects genuinely overlap a lot (two people hugging), a too-low IoU threshold deletes a correct detection. The threshold is a precision/recall knob, not a free cleanup. DETR avoids NMS entirely via Hungarian matching.
- **Why predict *deltas* off an anchor instead of absolute coordinates** is an *equivariance* argument, not just "it's easier." Conv filters are translation-equivariant — the same filter runs at every spatial location — so it should emit the *same correction style* everywhere ("nudge right a bit, grow 30%"), not different absolute coordinates per location. Absolute coords would force the filter to behave differently at every position, which a shared filter *can't* do well. Size deltas are in **log space** (`b_w = w_a·exp(t_w)`) so widths stay positive and `t_w=0` means "unchanged."
- **Semantic vs instance segmentation is a real distinction, not a synonym.** Semantic seg: every pixel gets a *class*, but two cats touching become one blob (no identity). Instance seg: every pixel gets class *and* an instance id (cat-1 vs cat-2 as separate masks). Mask R-CNN does instance; plain U-Net/DeepLab do semantic. Don't say "segmentation" generically when a student asks about separating two overlapping objects.
- **Dice loss exists because cross-entropy *fails under class imbalance* — and its gradient is non-local.** A mask that's 99% background optimizes plain pixel-CE to "predict background everywhere" (99% accurate, useless). Dice = $2|P\cap T|/(|P|+|T|)$ only counts pixels in the prediction or target, so the background sea of true-negatives doesn't dominate. Subtle point for the keen (P4): unlike per-pixel BCE (fully local), the Dice gradient at pixel $i$ depends on *all* target pixels through the shared $|P|,|T|,|P\cap T|$ terms.
- **mAP is averaged over IoU thresholds *and* classes — and "mAP" alone is ambiguous.** mAP@0.5 = AP at a single IoU cutoff of 0.5; mAP@[0.5:0.95] (the COCO headline) averages AP over ten thresholds 0.5→0.95, which is why it's always lower and rewards *precise* boxes. AP itself is the area under one class's precision-recall curve. If you just say "mAP went up," specify the protocol.
- **RoIAlign vs RoIPool is the trick that makes Mask R-CNN work.** Cropping region features by *rounding* to the nearest feature-map cell (RoIPool) shifts masks by several pixels — catastrophic for pixel-accurate masks. RoIAlign uses *bilinear sampling* (no rounding). If you cover Mask R-CNN at all, this is the one detail worth stating.

## Where students stumble (and the fix)
- **Box-format confusion in IoU.** Symptom: train loss falls but mAP ≈ 0. Fix: draw 5 predicted boxes on one image and *eyeball* them; confirm `xywh` vs `x₁y₁x₂y₂` before computing IoU. Make them compute one IoU on corner format by hand.
- **NMS misunderstood as "keep all high-confidence boxes."** Fix: the step-by-step board example — the point is that a *lower*-confidence box overlapping a kept one gets *deleted regardless of its own confidence*. Also remind them it's per-class.
- **Segmentation "99% accurate" but the mask is all background.** Symptom: high pixel accuracy, zero useful mask. Fix: print the foreground pixel fraction (often 1–5%); switch from plain CE to Dice or weighted CE. This is the most common segmentation failure.
- **U-Net masks find the object but boundaries are mush.** Symptom: blobby, imprecise edges. Fix: check that the decoder actually `cat()`s the matching-resolution encoder features at each level — dropped/misconnected skips are the cause. The skips *are* the boundary detail.
- **Small objects never detected.** Symptom: big objects fine, small ones invisible. Fix: histogram the ground-truth box sizes against the anchor sizes — anchors far larger than the objects means no anchor ever matches them.

## If a student asks…
- **"Why not just train a regressor to output, say, 10 boxes?"** (the pop-quiz hard one) Because the object count is *unknown and variable* — a fixed-output regressor breaks the moment there are 11 objects or 2. A detector predicts at every grid cell/anchor (so it scales to any count) and prunes with NMS. That's the property a classifier and a fixed regressor both lack.
- **"Why deltas off an anchor instead of predicting the box directly?"** Translation equivariance: the same conv filter runs everywhere, so it can only sensibly emit the *same kind of correction* at every location, not location-specific absolute coordinates. Anchors are the "starting corners"; the network learns small relative nudges (log-space for size, so widths stay positive). Far easier to learn and consistent across the image.
- **"Semantic vs instance segmentation?"** Semantic: pixel → class, no identity (two touching cats = one cat blob). Instance: pixel → class *and* which object (cat-1 vs cat-2 as separate masks). Use Mask R-CNN (or similar) when you must separate instances; U-Net/DeepLab give semantic masks.
- **"Why Dice instead of cross-entropy for masks?"** Class imbalance. With 99% background, plain CE is minimized by predicting background everywhere. Dice only counts foreground-relevant pixels (intersection over prediction+target sizes), so the background doesn't drown the signal. Reach for Dice (or weighted CE) first on imbalanced masks.
- **"What exactly is mAP@[0.5:0.95]?"** Average the average-precision over ten IoU thresholds from 0.5 to 0.95 (step 0.05), then average over classes. It rewards *precise* localization (a 0.9-IoU box scores at high thresholds; a 0.6-IoU box doesn't), which is why it's the COCO standard and always lower than mAP@0.5.
- **"One-stage vs two-stage — which should I use?"** Two-stage (Faster R-CNN): propose regions, then classify — more accurate (esp. small objects), slower. One-stage (YOLO): one grid pass — fast, production default. Real-time camera feed → YOLO (start with `ultralytics` YOLOv11); highest accuracy with a big backbone → Faster R-CNN variant. No universally-best detector.
- **"How does DETR get rid of NMS?"** It predicts a *fixed set* of 100 boxes and uses **Hungarian matching** to assign each ground-truth object to exactly one prediction (the rest match "no object"). One-to-one matching means no duplicates to suppress. Elegant, but slower and data-hungry — YOLO still wins on speed.
- **"What's SAM and when do I use it?"** Segment Anything (Meta, 2023): trained on ~1.1B masks, takes a prompt (point/box/text) and returns a mask *zero-shot* on unseen categories. Two caveats: it returns **masks, not labels** (pair with CLIP/a classifier for semantics), and quality is **prompt-sensitive** on niche domains. Default: start with SAM-2, fine-tune only for truly specialized domains (medical, satellite).

## If you're short on time
Cut: the NMS pseudocode, DETR + Hungarian matching, Mask R-CNN/RoIAlign, SAM, the open-vocabulary/CLIP shift, and the speed/accuracy table. Never cut: the **classification→localization→detection spectrum**, the **multi-task loss with `λ`**, the **IoU computation**, the **NMS board walk-through**, and the **U-Net skip-connection reason** (+ Dice for imbalance if there's room). Those carry the whole lecture and the diffusion-model callback later.

## Closing line
"Detection and segmentation don't replace the classifier — they bolt new heads onto the same backbone; the only thing that ever changes is the support of the random variable: one label, then one box, then many boxes, then one label per pixel."
