# Lecture 24 · Frontier — Agents · Reasoning · Interpretability · Teaching Guide
*First-time-instructor companion. Audience: undergrads, one ML course. The course finale.*

## The spine (say this in 2 sentences)
The 2024–2026 frontier is **not new architecture — it's new orchestration** of everything in L00–L23: agents = an LLM in a tool-call loop, reasoning models = an LLM with RL on its chain-of-thought plus a new scaling axis (test-time compute), and mechanistic interpretability = inspecting the residual stream and pulling features out of superposition. The course's one coherent story: differentiable modules, a likelihood, and scale.

## Where it sits
Builds on … *everything*. L15 LLMs (the base model under agents and reasoning) · L16 RLHF (reasoning models are RL on CoT; outcome vs process reward extends the reward-model idea) · L12/L13 attention + the residual stream (the object mech-interp reads) · L23 (test-time compute is only affordable because of efficient inference) · L18 (multimodal agents) · the whole "every loss is an NLL" through-line from L00.
Sets up … nothing — this is the finale. Its job is to give students the *taste* to place any new paper, plus a course recap and the closing send-off.

## 80-minute plan
- ⭐ Core (~40 min): agents as "brain in a jar gets hands and eyes" — the perceive-think-act / ReAct loop · function calling as "the model emits structured JSON; *your code* executes it and feeds the result back" · chain-of-thought (the 2022 discovery, emerges at scale) · reasoning models — outcome vs process reward, RL on CoT, spend 10–100× test-time compute · test-time compute as a *new scaling axis* (the college-exam analogy) · the residual-stream "shared whiteboard" view (the board example).
- ⭐⭐ Should-cover (~25 min): computer use (screenshot → mouse/keyboard actions) · the bat-and-ball worked example for rewarding chains · reasoning benchmarks (o1/o3 jumps on AIME, Codeforces) · superposition + sparse autoencoders (the dictionary / inverted-bottleneck analogy, Golden Gate Claude) · the open-problems short list · the 24-lecture arc recap.
- ⭐⭐⭐ Optional / skip-if-tight: the SAE math (encoder/decoder/L1 penalty) · the reasoning tree-search slide · the scaling-laws figure recap · detailed predictions for the field. One-line gist if asked about SAEs: "a neuron fires for many unrelated concepts (superposition); an SAE re-expresses the residual stream in a huge, mostly-zero dictionary so each *active* entry is one human-readable concept."
**Do live on the board:** the **residual stream as a shared whiteboard**. Write `h_{l+1} = h_l + attn(h_l) + ffn(h_l)`. Take a 4-D toy state `h_5 = [0.2, 0.5, 0.1, −0.9]`. Attention returns an *update* `[0.0, 0.3, 0.4, 0.0]` (boost features 2,3 from related tokens); FFN returns an *update* `[0.1, −0.1, 0.0, 0.2]`. Sum: `h_6 = [0.3, 0.7, 0.5, −0.7]`. The key insight to draw out: each block *reads* the stream and *adds* a contribution without erasing — so a "circuit" can write one isolated concept onto the bus and a later head can read it back. This makes induction heads and discovered circuits intuitive, and it's pure L12/L13 algebra they already know.

## Teach it like this
This is a literacy + send-off lecture, so trade derivation for placement: every frontier topic should land as "oh, that's just [earlier idea] wrapped in a loop / trained with RL / inspected." Open with the "which of these matters in 2030?" pop quiz to set the tone (judgment, not memorization). Demystify agents *hard* — the single most valuable correction you can make is "an agent is an LLM that outputs JSON, and a `while` loop that runs the tools; there is no agent neural network." Do the bat-and-ball example to show what process reward *means* (the greedy 10¢ trap vs the algebraic 5¢ chain). Frame test-time compute as the genuinely new thing since 2024 — a *second* scaling knob alongside training compute. Then the residual-stream board example for interpretability. Close on the open problems ("each is a PhD — pick one") and the course's one-coherent-story recap. Payoff: "the field is younger than you are; you now have the full vocabulary to read any paper and place it."

## Heads-up for YOU (subtle points to get right)  ← most important section
- **An "agent" is a system/deployment pattern, NOT a new architecture.** It's a standard LLM wrapped in a `while` loop: the model emits a structured tool call (just text/JSON), the *application layer* parses it, executes the real function, and appends the result to the next prompt. The LLM never "runs Python" or "calls an API" itself — it outputs a string and your code does the rest. Saying "agents are a new kind of network" is the headline misconception to kill.
- **Test-time compute is a real, distinct scaling axis — not the same as a bigger context window.** Two separate knobs now: (a) training compute → better general capability; (b) per-query reasoning compute → better on hard problems. Test-time compute = generating lots of *hidden* scratchpad tokens to explore reasoning before answering; context window = how much *input* you can read. OpenAI reported o1's benchmark scores scale smoothly with the inference-time budget — that smoothness is the claim that makes it a genuine axis.
- **Chain-of-thought may be UNFAITHFUL — the displayed reasoning is not guaranteed to be the model's actual cause.** A model can output a plausible step-by-step trace while internally relying on a different heuristic or bias (and can even be influenced by the prompt without mentioning it). This "faithfulness problem" is a live safety concern. Don't tell students "the reasoning trace shows you why the model answered" as established fact — present it as the *intended* behavior with a known gap.
- **Why o1 ≠ just prompting "think step by step":** plain CoT rides the pretrained distribution and can't recover from a mid-chain error. Reasoning models are *RL-trained* to explore, recognize dead-ends, backtrack, and optimize the *process* — the model learns to *do* search at inference, not just emit linear text. The difference is training, not a longer prompt.
- **Outcome reward ≠ process reward — and process reward (PRM) is the hard, important one.** Outcome reward checks only the final answer (cheap, verifiable, but no signal on *how*). A process reward model scores *each step* of the scratchpad (rich signal, but expensive to build — you need step-level labels or a learned PRM). The bat-and-ball example exists to make this concrete: same wrong final answer, but the *steps* are where the trap lives.
- **Mechanistic interpretability is more than "looking at attention maps," and it's still early/small-scale.** Attention maps show *where* information moves, not *what* it is. Modern interp (sparse autoencoders, dictionary learning) targets the *residual stream* to find the actual features/concepts. And be honest about maturity: most solid results are on small models or narrow circuits; scaling interp to GPT-4-class models is an open agenda, not a shipped engineering tool. Golden Gate Claude is a striking *demo*, not a routine debugging workflow.
- **Superposition is the *reason* SAEs exist — state it precisely.** A single residual-stream direction can encode many unrelated concepts (the model packs more features than dimensions). An SAE doesn't *create* the concepts; it re-expresses the dense vector in an overcomplete, L1-sparse basis (e.g. 100k features for a 12k-dim stream) so the few active entries become individually interpretable. It's untangling, not discovering.

## Where students stumble (and the fix)
- **Thinking the model "executes" tools.** Re-draw the loop: LLM → JSON string → *your harness* runs the tool → result string → back into the prompt → LLM. The LLM is the reasoning layer of a larger plain-software system. (Aside they'll love: this course's site was built by Claude Code, which is exactly this loop over bash/edit/read.)
- **Conflating "more reasoning" with "bigger model."** A reasoning model can have the *same* base capability as a non-reasoning one but is allowed scratch paper before answering. The college-exam analogy: training compute = years in college; test-time compute = pausing to work it out on scratch paper during the exam.
- **Believing the chain-of-thought is a transparent window into the model.** It's a useful artifact and often *correlated* with the real computation, but not guaranteed to *be* it (faithfulness gap). Say "it shows what the model wrote, which may or may not be why it answered."
- **Reading the residual stream as overwrite, not accumulate.** Each block *adds* to the stream (`h + attn + ffn`); it doesn't replace `h`. That additive, read-and-write-back structure is *why* circuits are findable — a concept written early survives to be read later. Emphasize the `+`.

## If a student asks…
- "Why can't I just prompt GPT-4 to 'think step by step' instead of using o1?" → Plain CoT uses the pretrained distribution and can't backtrack from a wrong step. o1 is RL-trained to explore, detect dead-ends, and optimize the reasoning *process* — it learned to search at inference time, which a prompt can't induce in a model that wasn't trained for it.
- "In the ReAct loop, how does the model actually call an API?" → It doesn't — it generates a structured string (JSON) naming the tool and arguments. Your surrounding program parses that, executes the real call, and pastes the result back as the next message. The model only ever outputs text.
- "What's the difference between test-time compute and a bigger context window?" → Context window = how much input you can *read*. Test-time compute = how many hidden reasoning tokens you *generate* before answering. One scales input capacity; the other scales the amount of search/thinking per query. They're orthogonal knobs.
- "(Hard) If an SAE dictionary is 100k-wide, how do you force sparsity without wrecking reconstruction?" → An L1 penalty on the activations drives most of the 100k entries to zero (typically 10–50 active per input). It works *because* the residual stream is already in superposition — all those concepts are present, packed densely; the SAE just rotates into an overcomplete basis where each is isolated. The reconstruction stays good because you're re-expressing, not compressing away, information.
- "Is the reasoning trace the real reason the model answered?" → Not guaranteed. The model can produce a sound-looking trace while internally using a different heuristic — the 'faithfulness' problem. It's often correlated with the real computation, which is why CoT helps, but treating it as a guaranteed explanation is unsafe. This is an open research question.
- "What's the Bitter Lesson and why does it keep coming up?" → Sutton's observation that general methods which *scale with compute* (search + learning) eventually beat hand-crafted human heuristics. It's the frame for the whole course: scaling laws, the Transformer's generality, and now reasoning models that *search* over thought at inference all keep proving it. When you bet on a frontier direction, bet on the one that scales.
