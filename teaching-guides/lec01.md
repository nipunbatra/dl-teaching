# Lecture 1 · Why Deep Learning? · Teaching Guide
*First-time-instructor companion. Audience: undergrads, one ML course.*

## The spine (say this in 2 sentences)
Deep learning = **representation learning**: instead of hand-engineering features and then drawing a boundary, you stack `linear → non-linearity` blocks and let gradient descent learn the features *and* the boundary end-to-end. The non-linearity is non-negotiable (stacked linear layers collapse to one), backprop is just the chain rule assigning blame layer by layer, and depth only became trainable once compute + data + algorithms (ReLU, init, residuals) crossed the line around 2012.

## Where it sits
Builds on … ES 335 (logistic regression, SVMs, decision trees on engineered features; gradient descent) · L00 (logistic/softmax classification = 1-layer net, same NLL loss) · L00C (CE = KL to one-hot truth).
Sets up … L02 (universal approximation, depth-vs-width, why depth, ResNets, Xavier/He init) and the whole architectural arc (CNNs → Transformers → LLMs).

## 80-minute plan
- ⭐ Core (~45 min): "DL = representation learning" · the neuron = sum + squash · **why stacking linear layers collapses** (`W₂(W₁x+b₁)+b₂ = W_eff x + b_eff`) and the numeric check · why the non-linearity bends space · **XOR** (linear can't, 2-hidden-ReLU MLP can — built by hand) · the softmax+CE gradient `ŷ − y` · backprop as "the blame game" + the three linear-layer rules (`δxᵀ`, `δ`, `Wᵀδ`). Every student must leave knowing why non-linearity is mandatory and what backprop computes.
- ⭐⭐ Should-cover (~25 min): parameter counting (MNIST 256-256 → 269,322) · the PyTorch MLP (Sequential vs explicit) · the **bare-last-layer / double-softmax** bug (loss stuck at 2.30) · the end-to-end 1-1-1 backprop-by-hand · vanishing gradients (σ′ ≤ 0.25, `0.25⁵ ≈ 0.001`) · ReLU as the fix · the three axes (expressivity / trainability / generalization).
- ⭐⭐⭐ Optional / skip-if-tight: the three-eras history, ImageNet table, "why now / three ingredients," Hubel-Wiesel biology, train/val/test split honesty, train vs eval mode — all valuable context but cuttable. Gist if asked about *why now*: "compute, data, and algorithms each ramped for 30 years; 2012 (AlexNet, 16.4% ImageNet top-5) is when all three crossed at once — DL didn't get smarter, the world got faster."
**Do live on the board:** the **XOR 2-layer MLP forward pass**. Draw the fixed weights (`W₁=[[1,1],[1,1]]`, `b₁=[0,−1]`, `w₂=[1,−2]`, `b₂=0`), then push `(1,1)` through: pre-activation `(2,1)`, ReLU keeps `(2,1)`, output `2−2 = 0`; do `(0,1)` → `(1,0)` → `1`. Outputs `0,1,1,0` = exactly XOR. It lands because they *watch* the ReLU "kink" bend a point that no line could separate — the single clearest "why non-linearity" moment in the course.

## Teach it like this
Open by pointing their ES 335 toolkit at a raw `224×224×3 = 150,528`-pixel photo and asking "why does this fail?" (no translation prior + curse of dimensionality). Define DL in one sentence — *representation learning with differentiable composable modules trained end-to-end* — then *prove* the central claim live: stacking linear layers collapses (algebra + numbers), so depth without non-linearity is worthless. XOR is the payoff: the smallest problem no line can solve, solved by hand with two ReLU units. Then flip to learning: softmax+CE gives the clean `ŷ − y` gradient, backprop carries it backward as "blame," and the lecture ends on the honest cost of depth — vanishing gradients — which is the cliffhanger into L02's fixes (ReLU, init, residuals).

## Heads-up for YOU (subtle points to get right)  ← most important section
- **Backprop ≠ training; backprop ≠ gradient descent.** Backprop only *computes the gradients* (it's reverse-mode autodiff = the chain rule applied in reverse topological order). Gradient descent / Adam is the *optimizer* that uses those gradients to update weights. Don't say "backprop trains the network" — say "backprop computes gradients, SGD updates."
- **`ŷ − y` is the gradient w.r.t. the LOGIT, not the weight.** Write it as `∂L/∂z_k = ŷ_k − y_k`. The weight gradient is `(ŷ − y) xᵀ` (the outer product). If you call "`ŷ − y`" *the* gradient without "of the logit," a sharp student notices it can't be the weight gradient (wrong shape). Also note `y` here is the one-hot target.
- **The input gradient is `Wᵀδ`, transpose required.** `∂L/∂x = Wᵀδ` (not `Wδ`). The transpose projects the error from output-space back to input-space; without it the dimensions don't even conform. Same for `∂L/∂W = δxᵀ` — get the outer-product order right (`δ` is a column, `xᵀ` a row).
- **Vanishing gradients are caused by the *activation's derivative*, not by depth per se.** Depth merely *exposes* the collapse: the chain rule multiplies many factors each `≤ 1` (sigmoid's max is `σ′(0)=0.25`), so `0.25⁵ ≈ 0.001`, `0.25¹⁰ ≈ 10⁻⁶`. The fix is changing the activation (ReLU, derivative 0 or 1), not just "use fewer layers." Don't say "deep networks can't train" — say "*sigmoid* deep networks can't, because of repeated sub-1 multiplication."
- **The 2.30 stuck-loss is `ln 10`, not `log₁₀`.** A model predicting uniform `1/10` over 10 classes gives `−ln(1/10) = ln 10 ≈ 2.3026` (PyTorch CE uses *natural* log). If you say "log 10 = 1" you'll get a wrong, confusing number. This is the signature of (a) an untrained model or (b) the double-softmax bug.
- **The double-softmax bug crushes gradients, it doesn't just "double-apply."** `nn.CrossEntropyLoss` internally does `log_softmax`. Adding your own `nn.Softmax()` in `forward` means softmax-of-softmax: the inputs to the loss are already squashed into a tight near-uniform range, so gradients become tiny and learning stalls near 2.30. The fix: last layer outputs *raw logits*.
- **Forgetting `zero_grad()` accumulates, it doesn't instantly explode.** PyTorch *adds* each `.backward()` into `.grad`. After k batches you're stepping with `g₁+g₂+…+g_k` — effectively a *growing* learning rate, so the loss drifts/diverges *over steps*, not in one bang. Diagnose by watching `p.grad.norm()` climb.

## Where students stumble (and the fix)
- **"Why don't the non-linearities collapse like the linear layers do?"** Because `σ(W₂σ(W₁x))` is *not* expressible as `W_eff x` — only linear maps compose into a linear map. The non-linearity permanently bends the coordinate space; that's the entire point. (Pair this with the XOR board demo.)
- **Believing more parameters = deep learning.** The change isn't parameter count — it's that each layer *learns a transformation* (pixels→edges→parts→objects). The final softmax is just logistic regression on features the network designed for itself.
- **Putting a softmax/sigmoid after the last `Linear`.** Drill the rule: classification heads output *raw logits*; the fused loss (`CrossEntropyLoss`, `BCEWithLogitsLoss`) applies the squash internally and stably (log-sum-exp). Plain `BCELoss`/`NLLLoss` are the ones that expect post-activation inputs.
- **Off-by-transpose / shape errors in backprop.** Have them write the three rules with explicit shapes once: `δ ∈ ℝ^{d_out}`, `x ∈ ℝ^{d_in}` ⇒ `∂L/∂W = δxᵀ ∈ ℝ^{d_out×d_in}`, `∂L/∂x = Wᵀδ ∈ ℝ^{d_in}`. Shapes are the fastest correctness check.

## If a student asks…
- "If a single hidden layer can approximate any function (UAT), why go deep?" → UAT is about *expressivity* (it *can* represent it) — it says nothing about how *wide* (often exponentially) or whether SGD can *find* it. Depth gives compact, hierarchical, reusable features and is usually far more parameter-efficient and trainable. (Full answer is L02.)
- "ReLU's derivative is 0 for negative inputs — doesn't that cause dead neurons?" → Yes, the "dying ReLU": if a large update pushes a unit's pre-activation deeply negative, it outputs 0, its local gradient is 0, and it may never recover. Mitigations: smaller LR, good init, or Leaky/GELU variants. But ReLU's derivative being *exactly 1* when active is precisely why it beats sigmoid for depth.
- "If `∂L/∂W = δxᵀ`, a zero input gives zero weight gradient — is that a problem?" → Yes; a feature stuck at 0 gets no gradient for that sample. This is one reason we center/normalize inputs (zero-mean) — to keep gradient signal flowing consistently across features.
- "Does backprop need the chain rule to be done by hand?" → No — it's reverse-mode autodiff, mechanical. PyTorch records the computation graph on the forward pass and replays it backward applying the same local rules (`δxᵀ`, `Wᵀδ`). The micrograd notebook builds this engine from scratch.
- "Why did this work in 2012 and not 1990?" → Same ideas (backprop is 1986, CNNs 1989), but three things compounded: GPUs (compute), ImageNet (1.2M labeled data), and algorithmic fixes (ReLU, better init, dropout). AlexNet (2012) cut ImageNet top-5 error from ~26% to 16.4% in one year.
- "How is the bias gradient computed if the bias multiplies nothing?" → Treat bias as a weight on a constant input of 1. Then `∂L/∂b = δ·1 = δ` — it falls straight out of the same `δxᵀ` rule.
- "Why does `CrossEntropyLoss` want logits instead of probabilities?" → Two reasons: numerical stability (fused log-softmax uses log-sum-exp, avoiding overflow/`log(0)` from a separate softmax) and a cleaner, more stable gradient (`ŷ − y`). Feeding probabilities forces the unstable `log(softmax(x))` path.

## If you're short on time
Cut: the history/ImageNet/"why now"/biology block, train/val/test honesty, and train-vs-eval mode (all great context, none load-bearing for the core idea). Never cut: the **linear-collapse proof + XOR by hand** (why non-linearity exists) and the **backprop three-line rule** (`δxᵀ, δ, Wᵀδ`) with the end-to-end numeric — those two *are* the lecture.

## Closing line
"Deep learning is one move: stop *engineering* the representation and start *learning* it — stack `linear → bend`, let backprop assign blame, and let SGD do the rest."
