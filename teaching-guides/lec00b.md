# Lecture 0B · Bayes, MAP, Regularization & KL · Teaching Guide
*First-time-instructor companion. Audience: undergrads, one ML course.*

## The spine (say this in 2 sentences)
Last lecture, "loss" came from a likelihood; this lecture, "regularizer" comes from a *prior* — `MAP = MLE + a prior on θ`, and the log-prior literally *is* the penalty term. L2 is a Gaussian prior, L1 is a Laplace prior, and KL divergence is the one distance-between-distributions that ties MLE, regularization, and every generative loss ahead into a single "fit the data + don't drift" template.

## Where it sits
Builds on … L00 (likelihood, NLL, MSE/BCE/CE) · ES 335 (you used ridge/lasso as knobs without knowing why).
Sets up … L00C (the bits/coding meaning of entropy and KL), and the generative half of the course — VAE (L19), diffusion (L21), RLHF/DPO (L16), distillation (L23) — all of which are "minimize a specific KL."

## 80-minute plan
- ⭐ Core (~40 min): Bayes' rule with the four named terms (posterior/likelihood/prior/evidence) · why we drop the evidence for a point estimate · MLE's trap (3 heads → `p̂=1.0`) motivating a prior · **MAP = MLE + log-prior** · Gaussian prior → **L2** (full derivation) · Laplace prior → **L1** · why L1 zeroes weights and L2 doesn't. Every student must leave able to say "every regularizer is a prior."
- ⭐⭐ Should-cover (~30 min): the disease-test Bayes example (base-rate fallacy) · KL as "extra surprise / extra bits," `KL ≥ 0`, asymmetry · `cross-entropy = entropy + KL` and the one-hot collapse `CE = KL = NLL` · `weight_decay` IS the Gaussian prior (the AdamW caveat) · forward vs reverse KL (mode-covering vs mode-seeking).
- ⭐⭐⭐ Optional / skip-if-tight: the **Jensen's-inequality proof that KL ≥ 0** (slide is already marked ⭐⭐⭐) — gist if asked: "log is concave, push the expectation inside with Jensen, the ratio integrates to 1, so −KL ≤ log 1 = 0; same trick reappears in the VAE's ELBO." Also the MLE/MAP-through-the-KL-lens slides can be summarized in one sentence.
**Do live on the board:** the **L1-vs-L2 scalar update** (slide "L1 zeroes a weight, L2 doesn't"): θ=0.05, g=0.3, λ=0.5, η=1. L2: `θ ← 0.05 − (0.3 + 2·0.5·0.05) = −0.30` (overshoots past zero). L1/ISTA: data step `0.05 − 0.3 = −0.25`, then soft-threshold with `ηλ=0.5`: `sign(−0.25)·max(0.25−0.5, 0) = 0`. It lands because students *see* the exact zero appear from the soft-threshold — the abstract "diamond geometry" becomes one line of arithmetic.

## Teach it like this
Start with the pop quiz "L2 is squared, L1 is absolute — (a) coincidence, (b) arbitrary, (c) each is a log-prior" and make them commit, because the whole lecture is the answer (c). Anchor MAP on the absurd coin (3 heads → MLE says the coin *can never land tails*) — that visceral failure is why a prior exists. Then run the identical algebra twice — Gaussian prior gives the squared penalty, Laplace gives the absolute penalty — so they feel that L1 and L2 are the *same machinery, different prior*. Close by zooming out: the same `fit + don't-drift-in-KL` shape is VAE, RLHF, and distillation, so today buys ten future lectures.

## Heads-up for YOU (subtle points to get right)  ← most important section
- **MAP is a POINT estimate, not "the distribution over θ."** MAP returns the single most probable θ (the *mode* of the posterior). It is not Bayesian inference — that keeps the whole posterior. Don't say "MAP gives you the posterior"; say "MAP gives you the *peak* of the posterior."
- **The factor of 2 and the sign in `λ = 1/(2σ_p²)`.** Gaussian log-prior is `−θ²/(2σ_p²) + const`. In MAP you *subtract* the log-prior (`L_NLL − log p(θ)`), and the two minus signs make it `+ (1/2σ_p²)‖θ‖²`. So `λ = 1/(2σ_p²)`, which means **small prior variance ⇒ large λ ⇒ strong penalty**. If a student computes the prior variance for `weight_decay=1e-4`: `σ_p² = 1/(2·1e-4) = 5000` — a *weak* prior that permits fairly large weights. Get the direction right (small σ_p² ↔ big λ) or the intuition inverts.
- **`weight_decay` in plain SGD = L2; in *Adam* it is NOT equivalent to L2.** This is the single highest-value gotcha. With SGD, decoupled weight decay and adding `λ‖θ‖²` to the loss coincide. With Adam they do *not*: L2-in-the-loss gets divided by the per-parameter adaptive denominator (so large-gradient weights get *less* effective decay), which is wrong. **AdamW** fixes this by applying the decay directly to the weights, *outside* the momentum/variance tracking — recovering the true Gaussian-prior/MAP update. Don't tell them "AdamW and Adam-with-L2 are the same."
- **L1's sparsity comes from the *constant* gradient, i.e. the kink at 0.** L2's penalty gradient is `2λθ` — it shrinks proportionally and *vanishes as θ→0*, so it never finishes the job. L1's penalty gradient is `λ·sign(θ)` — a constant pull that doesn't weaken near 0, so it drives weights *exactly* to 0. Frame it as "constant force vs fading force," not just "diamond has corners."
- **KL is directed, not a distance.** `KL(p‖q) ≠ KL(q‖p)` and it violates the triangle inequality — it is not a metric. `KL(p‖q)` = expected *extra* bits to encode draws from the truth `p` using a code built for the model `q`. State the direction every single time you write KL; the whole forward/reverse story depends on it.
- **MLE = KL minimization uses FORWARD KL.** MLE = `arg min KL(p̂_data ‖ p_θ)` — the *empirical distribution first*, model second. This is forward KL, which is **mode-covering** (it must put mass wherever the data has mass). So MLE-trained models are mode-covering *by construction* — that's why a single Gaussian fit to bimodal data goes blurry-in-the-middle, and why VAE samples blur. Do not say reverse KL.
- **`cross-entropy = KL` ONLY when the target is one-hot.** In general `H(p,q) = H(p) + KL(p‖q)`. The classification loss equals the KL *because the one-hot label has entropy 0*. The moment you use **label smoothing**, `H(p) > 0` and CE ≠ KL anymore (CE picks up a constant floor). Don't state "cross-entropy is KL" unconditionally.

## Where students stumble (and the fix)
- **"95% accurate test, positive result → 95% sick."** Run the disease numbers live: prevalence 1%, sens 95%, spec 95% → `P(+) = 0.95·0.01 + 0.05·0.99 = 0.059`, so `P(D|+) = 0.0095/0.059 ≈ 16%`. The false positives from the huge healthy majority swamp the true positives. (Practice P2 variant: prevalence 0.5%, sens 99%, spec 95% → `P(+)=0.0547`, `P(D|+)≈9%`.)
- **Forgetting the minus sign when going from log-prior to penalty.** Make the `L_NLL − log p(θ)` → `L_NLL + λ‖θ‖²` sign-flip explicit on the board; it's where they drop a sign and get a *reward* for large weights.
- **Thinking the evidence `p(D)` matters for finding θ.** It's constant in θ, so it drops out of any `arg max`/`arg min`. It only matters for the *full* posterior (Bayesian NN, model comparison, the ELBO denominator) — not for MLE/MAP point estimates.
- **Reading forward/reverse KL backwards.** Tie each to *what you average over*: forward averages over the truth `p` (so it can't ignore any region `p` covers → mode-covering); reverse averages over the model `q` (so `q` plays it safe and hides in one mode → mode-seeking).

## If a student asks…
- "What prior variance does `weight_decay=1e-4` correspond to?" → `λ = 1/(2σ_p²)`, so `σ_p² = 1/(2·1e-4) = 5000`. The implied prior is `N(0, 5000)` — it believes weights are *centered at 0* but allows them to be sizeable, just not unbounded.
- "Is `weight_decay` in Adam the same as adding `λ‖θ‖²` to the loss?" → No. In Adam the L2 gradient gets rescaled by the adaptive denominator, so it's not a clean Gaussian prior. AdamW decouples the decay (applies it straight to the weights) to recover the correct MAP/weight-decay behavior. This is *the* reason AdamW exists.
- "Why KL and not just Euclidean distance between probability vectors?" → Because KL is the quantity that connects to likelihood and coding: minimizing `KL(p̂_data‖p_θ)` is *identical* to minimizing NLL, and KL = "extra bits wasted." Euclidean distance has no such interpretation and isn't what MLE optimizes.
- "If KL is asymmetric, which direction is 'correct'?" → Neither — it's a modeling choice with different failure modes. Forward (mode-covering, what MLE does) gives safe-but-blurry; reverse (mode-seeking, roughly what VAE encoders / GAN training lean toward) gives sharp-but-collapse-prone. Knowing your loss's direction predicts the failure.
- "Does MAP always beat MLE?" → No. With abundant data the likelihood dominates and MAP → MLE; the prior only matters when data is scarce — which is exactly when overfitting bites, so that's when it helps. A badly chosen prior can hurt.
- "Why is L1 not just a built-in optimizer flag like weight decay?" → Because of the kink at 0: the gradient is undefined there, so naive subgradient descent rarely hits *exact* zero. You either add `λ·w.abs().sum()` to the loss manually, or use proximal/ISTA soft-thresholding, which produces true zeros (the board example).
- "Compute `KL(N(2,0.25)‖N(0,1))`?" → Closed form for `KL(N(μ₁,σ₁²)‖N(μ₂,σ₂²)) = log(σ₂/σ₁) + (σ₁²+(μ₁−μ₂)²)/(2σ₂²) − ½`. Here `= log(1/0.5) + (0.25+4)/2 − 0.5 = 0.693 + 2.125 − 0.5 ≈ 2.32` nats. Large, because the model is centered far from the truth.

"There is no separate theory of losses and regularizers — it's one Bayesian story: the likelihood gives the loss, the prior gives the penalty, and *every regularizer you've ever used is a prior in disguise*."
