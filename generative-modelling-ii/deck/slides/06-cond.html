What the network receives from a prompt

The prompt becomes 77 vectors, computed once and reused at every one of the denoising steps.

computed real CLIP tokenizer

The CLIP tokenizer (the one Stable Diffusion v1 uses) splits our prompt into 5 word tokens plus start and end markers. Padded to a fixed length of 77.

The real token IDs, from running the tokenizer. IDs are arbitrary labels: "basket" is 10338 only because of the vocabulary order; remember this in Part 7.

A frozen text encoder turns them into 77 vectors. You trained this kind of encoder in the CLIP lecture; Stable Diffusion v1 uses CLIP ViT-L/14's text tower, 768 numbers per token. (The LDM paper's own text model, which produced the cherry images, used a BERT tokenizer and a transformer trained jointly.)

The same C is used at every step; only the noisy image changes.

Cross-attention, reversed from the VLM lecture

Image positions ask questions; words supply the answers

In a VLM, text queried image features. Here image features query the text: each position pulls in the words relevant to it.

illustrative weights

Inside the U-Net, the feature map at some resolution has N = H × W positions. Each position makes a query. The highlighted cell is one position.

The 77 text vectors make keys and values (only the five word tokens are drawn).

Scores between that position's query and every word's key, softmax over the words: one row of the N × L attention matrix. The weights here are illustrative, not extracted from a model.

The output is a weighted sum of value vectors, added back to that position's features. Shapes: Q is [B, N, d], K and V are [B, L, d], A is [B, N, L], AV is [B, N, d]. Heads are in appendix A11.

Our class-conditional model

Train one network with the label, and sometimes without it

c = torch.where(torch.rand(B) < 0.1, torch.full_like(c, 10), c)   # 10 means "no label"
eps_hat = model(xt, t, c)

The same weights now give two predictions for any noisy image: $\epsilon_c$ with the label and $\epsilon_u$ without.

our model

Same U-Net, plus a learned embedding of the digit label added to the time embedding. Labels are a simpler condition than text, and enough to show guidance on MNIST.

10% of the time the label is replaced by a special "none" index, with the same input and the same noise target. Our implementation of "no condition" is that extra embedding row; Stable Diffusion uses the empty prompt's encoding.

Classifier-free guidance

Guidance: step past the conditional prediction

$\epsilon_{\text{cfg}} = \epsilon_u + s\,(\epsilon_c - \epsilon_u)$

$s = 0$: ignore the label · $s = 1$: ordinary conditional · $s > 1$: exaggerate the label's direction

Our model, label 7, one noisy blank page at t = 600: the implied clean image for each prediction.

Two network calls per step, combined by one line of arithmetic. No separate classifier is trained.

our model bottom row

The unconditional prediction, drawn as a 2-D vector (illustrative numbers, equal axis scales).

The conditional prediction. Their difference is "what knowing the label changes".

Guidance scale 3 goes three times as far along that difference.

Real images from our model. Without the label the guess is a vague blob; with it, a faint 7; at s = 3, a bold 7. Guidance sharpens what the label implies.

Turning up guidance trades variety for fidelity

“Look like a 7”: a separate MNIST classifier's verdict on all 64 samples. Spread: average pixel distance between samples. 8 of 64 shown.

At s = 1, {{cfg.1.frac7}}% already look like a 7. Larger s gives {{cfg.7.frac7}}%, with bolder and more alike strokes: spread {{cfg.1.div}} → {{cfg.7.div}}.

our model

s = 0 ignores the label: any digit.

s = 1, the plain conditional model. {{cfg.1.frac7}}% are already sevens: on MNIST a digit label is a strong, simple condition. Text prompts are followed much less reliably at s = 1, which is why guidance matters more for text-to-image.

s = 3: nearly all sevens.

s = 7: thick, similar sevens. Spread falls as s grows. Text-to-image systems typically use s around 5–10 for the same reason: prompts are followed more literally, at the cost of variety and sometimes saturated colours.

Back to the opener: filling a missing region

Inpainting with our model: paste the known pixels back in

six samples:

No retraining: known pixels come from the forward process, unknown ones from the reverse step. Different seeds give different digits that agree with the top half.

our model

We keep the top half of our 7 and hide the bottom.

Each step: the model proposes x_{t−1} for the whole image; we overwrite the known region with the clean pixels noised to step t−1 using the exact forward formula. This is RePaint's core idea; RePaint also re-noises and repeats some steps ("resampling") to blend the two regions better, which we skip.

Six seeds. Ask: are they all sevens? The top bar of a 7 is shared by several digits, so the model is free to choose. That is the conditional distribution from the opening slide.

our model

The sketch: our 7 reduced to 7 × 7 blocks. Noise it to t₀ = 200 with the jump formula and run only the last 200 reverse steps. The blocks are smoothed but the shape stays.

Larger t₀ gives the model more freedom: by 800, outputs are clean handwritten digits, not necessarily faithful to the sketch. This is SDEdit, and it supports the claim made on the opening slide.

The same sampler loop from Part 3, with conditions added

Guidance and inpainting are a few changed lines

x = torch.randn(B, 1, 28, 28)
for t in range(T, 0, -1):
    tt = torch.full((B,), t)
    eps_u = model(x, tt, none)                 # label hidden
    eps_c = model(x, tt, label)                # label 7
    eps_hat = eps_u + s * (eps_c - eps_u)      # guidance
    c = beta[t] / (1 - alpha_bar[t]).sqrt()
    mean = (x - c * eps_hat) / alpha[t].sqrt()
    x = mean + post_var[t].sqrt() * torch.randn_like(x) if t > 1 else mean
    known_t, _ = corrupt(x_known, torch.full((B,), t - 1))
    x = mask * known_t + (1 - mask) * x       # inpainting
guidance: two calls, one line of arithmetic
inpainting: overwrite the known pixels, noised to the next step
SDEdit: change only the first line, start from the noised sketch at $t_0$

The trained network never changes; only how we call it and what we do with its output.

Classifier-free guidance: run the network with and without the label (in practice as one batch of 2B) and combine.

Inpainting with an unconditional model: after each step, replace the known region with the clean pixels noised to step t−1 (corrupt() from Part 1; at t = 1 that is the clean image itself).

SDEdit replaces the first line: x = corrupt(sketch, t0) and the loop starts at t0. Super-resolution is the exception: the low-res image is an extra input the network was trained with.

Super-resolution: feed the low-res image in as extra channels

+ →network6 input channels→ ⇒

Unlike inpainting, this needs a model trained with the low-res input. And, as with our lab images, the added detail is a sample, not a measurement.

published

SR3, Saharia et al. 2022. Diagram: the conditioning scheme described in the paper (concatenation of the upsampled input).

SR3 concatenates the upsampled low-resolution image to the noisy high-resolution state: 3 + 3 = 6 input channels. Trained on (low-res, high-res) pairs with the usual noise target.

Contrast with our inpainting: there the unconditional model needed no retraining because the condition is "these pixels are known exactly". Here the condition is indirect, so the model must learn how it relates to the image.
