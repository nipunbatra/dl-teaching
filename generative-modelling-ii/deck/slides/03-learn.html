Part 1 gave us a way to make noisy images. Goal of this part: turn that into (input, label) pairs and a loss, so that a network learns to predict the noise, and see what it can and cannot learn.

$\hat\epsilon^\star = \mathbb E[\epsilon\mid x_2] = 0.90(-0.5) + 0.10(2.17) = \mathbf{-0.24}$

Squared error is smallest for the average of everything that could have happened, not for the true −0.5.

* if ink and paper were equally likely before we looked

$\mathbb E[x_0\mid x_2] = 0.90(+1) + 0.10(-1) = 0.80$: a grey pixel.

This is why regression blurs (the SR3 slide): it returns an average. Diffusion uses that average to take one small step, not as the final image.

computed

The network sees x₂ = 0.5 (and the neighbours). Two worlds are consistent with it: ink with ε = −0.5, or paper with ε = +2.17. The ink world is 9.2 times more likely under the Gaussian noise, so 0.90 vs 0.10.

Minimising expected squared error gives the conditional mean, −0.24. Even a perfect network does not output the true −0.5. Remember this for the sampler: ε̂ is a best guess, not the truth.

In clean-image terms the best guess is 0.80: neither ink nor paper. Over a whole image these averages are what makes regression blurry. Neighbouring pixels sharpen the posterior: a pixel surrounded by ink is probably ink. That is the information the network adds.

Ask: should the network subtract the same amount of noise from all three? No: from the left one almost nothing, from the right one almost everything.

Could the network infer t from the image? Roughly, but telling it is cheap and exact. Training one shared network, rather than 1000, is what makes this practical.

Shapes, in a batch

A batch mixes noise levels: one $\bar\alpha$ per image

Random t per image means every batch trains the network at many noise levels at once.

The complete training step

The whole training step in PyTorch

beta = torch.cat([torch.zeros(1), torch.linspace(1e-4, 0.02, 1000)])
alpha_bar = torch.cumprod(1 - beta, 0)     # once, as in Part 1

t   = torch.randint(1, T + 1, (B,))        # a step per image
eps = torch.randn_like(x0)                 # the label
ab  = alpha_bar[t].reshape(B, 1, 1, 1)
xt  = ab.sqrt() * x0 + (1 - ab).sqrt() * eps
eps_hat = model(xt, t)
loss = F.mse_loss(eps_hat, eps)
opt.zero_grad(); loss.backward(); opt.step()

No reverse chain, no sampling loop: one random step per image, one forward pass, one MSE.

The tables have 1001 entries so that index t means step t; entry 0 is the clean image. Off-by-one errors here are the most common bug in student code.

t and ε are both random. ε is kept: it is the label.

The computation graph

Gradients flow only into the network's weights

$x_0$, t and $\epsilon$ are constants made before the forward pass; only $\theta$ gets a gradient.

Forward pass: data, a random draw and a random step make x_t with no parameters involved. Only the network has weights. ε also travels separately to the loss as the label.

The loss compares ε̂ with ε: one number per batch.

Backward: the gradient reaches θ through ε̂. Nothing upstream of the network has parameters, so nothing else is updated. Contrast with Lecture I's VAE, where gradients had to pass through a random draw (reparameterisation); here the draw is outside the graph.

The loss drops fast and then slowly: the curve is on a log scale.

Ask why small t is hard. At t = 1 the noise is tiny (scale 0.01) and nearly invisible against the digit, yet the network must report it at unit scale. At t = 1000 the input is almost exactly ε, so copying the input is nearly right. This unevenness is exactly what the ELBO weights on the next slides are about.

What we did, and what comes next

What we did

  1. A training example is (noisy image, step t) as input and the noise $\epsilon$ as the label.
  2. The loss is plain squared error over 784 pixels; one random t per image, no loop.
  3. Even a perfect network cannot recover $\epsilon$ exactly; it predicts the average of what is possible: −0.24 for our pixel.
  4. Our network: 814,145 parameters, 30,000 steps, hardest at small t.
