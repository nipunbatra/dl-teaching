The forward step

One step: shrink the image a little, then add fresh noise

$$x_t = \sqrt{1-\beta_t}\;x_{t-1} + \sqrt{\beta_t}\;\eta_t, \qquad \eta_t \sim \mathcal N(0, I)$$

With β = 0.2, our pixel goes from 1 to 0.671. Each step keeps most of the image and mixes in a little noise.

computed β = 0.2 so you can see it

Multiply every pixel by √(1 − β). With β = 0.2 that is 0.894: the 7 gets slightly paler.

Draw a brand-new noise image η, the same shape as the digit, and scale it by √β = 0.447.

Add them. β_t is the noise variance added at step t.

Our pixel: 0.894 × 1 + 0.447 × (−0.5) = 0.671, taking η = −0.5 at our pixel. The real schedule uses β between 0.0001 and 0.02; we use 0.2, ten times the largest, so one step is visible.

The square roots keep the total variance at 1, so after many steps we land exactly on a standard Gaussian, $\mathcal N(0, I)$.

computed

Ask the slide's question before clicking: why √(1 − β) and √β, not (1 − β) and β?

Scaling a random variable by a multiplies its variance by a². Independent variances add. So 0.8 + 0.2 = 1.

Without roots the variance decays towards 0, and the end point would depend on the step count. With them, the end point is always N(0, I): something we can sample from.

The forward process in code

Everything in Part 1 fits in a few lines of PyTorch

beta = torch.cat([torch.zeros(1),        # beta[0] = 0
                  torch.linspace(1e-4, 0.02, 1000)])
alpha = 1 - beta
alpha_bar = torch.cumprod(alpha, 0)      # [0] = 1

def corrupt(x0, t):       # x0 [B,1,28,28], t [B]
    eps = torch.randn_like(x0)
    ab = alpha_bar[t].reshape(-1, 1, 1, 1)
    return ab.sqrt() * x0 + (1 - ab).sqrt() * eps, eps

Answer to question 1, and the setup for question 2

Forward is a fixed recipe; reverse is a model we must learn

$$q(x_t\mid x_{t-1}) = \mathcal N\big(\sqrt{1-\beta_t}\,x_{t-1},\ \beta_t I\big)$$
$$p_\theta(x_{t-1}\mid x_t) = \mathcal N\big(\mu_\theta(x_t,t),\ \sigma_t^2 I\big)$$

Each reverse step only has to undo a small step, which is why a Gaussian with a learned mean is a good model of it.

Top arrows: the corruption we just built. Fixed β's, no parameters, nothing to learn. Real images at t = 0, 100, 300 and 1000.

Bottom arrows: what we want, a network that takes x_t and t and proposes x_{t−1}. Because each forward step is tiny, the true reverse step is close to Gaussian; we only need to learn its mean. That is Part 2.

computed

The network sees x₂ = 0.5 (and the neighbours). Two worlds are consistent with it: ink with ε = −0.5, or paper with ε = +2.17. The ink world is 9.2 times more likely under the Gaussian noise, so 0.90 vs 0.10.

Minimising expected squared error gives the conditional mean, −0.24. Even a perfect network does not output the true −0.5. Remember this for the sampler: ε̂ is a best guess, not the truth.

In clean-image terms the best guess is 0.80: neither ink nor paper. Over a whole image these averages are what makes regression blurry. Neighbouring pixels sharpen the posterior: a pixel surrounded by ink is probably ink. That is the information the network adds.

The computation graph

Gradients flow only into the network's weights

$x_0$, t and $\epsilon$ are constants made before the forward pass; only $\theta$ gets a gradient.

Forward pass: data, a random draw and a random step make x_t with no parameters involved. Only the network has weights. ε also travels separately to the loss as the label.

The loss compares ε̂ with ε: one number per batch.

Backward: the gradient reaches θ through ε̂. Nothing upstream of the network has parameters, so nothing else is updated. Contrast with Lecture I's VAE, where gradients had to pass through a random draw (reparameterisation); here the draw is outside the graph.

Taking the bound apart

The bound splits into one comparison per step

$$-\text{ELBO} = \cz{L_T} + \sum_{t=2}^{T}\cdec{L_{t-1}} + \cx{L_0}$$
$$\cdec{L_{t-1}} = \mathbb E_{q}\, D_{KL}\big(\,q(x_{t-1}\mid x_t, x_0)\;\|\;p_\theta(x_{t-1}\mid x_t)\,\big)$$

$L_T$ has no parameters; $L_0$ is a small pixel-level term. Training is really about the middle terms.

L_T: does the end of the forward chain match N(0, I)? With ᾱ_T = 0.00004 it almost exactly does, and there is nothing to learn.

The middle terms compare, at each step, the network's reverse step with the "true" reverse step q(x_{t−1} | x_t, x₀). That true step is a Gaussian we can write down because we know x₀ during training (appendix A2).

L₀ turns the last continuous state into pixel values. DDPM treats it separately. Next: one middle term, with numbers.

The qualification

DDPM keeps the squared error and drops the weights

$$L_{\text{simple}} = \mathbb E_{x_0, t, \epsilon}\,\|\epsilon - \epsilon_\theta(x_t, t)\|^2$$

The bound's weight falls about 109× from t = 2 to t = 500. Setting every weight to 1 gives relatively more weight to noisy steps than the bound does.

It also drops $L_T$ (no parameters) and the discrete pixel term $L_0$.

The training loss is not the ELBO; it is a re-weighted sum of its per-step terms, chosen because it gave better samples (Ho et al. 2020).

The bound cares most about the last few low-noise steps, which mostly polish imperceptible detail. The simple loss spends more effort on mid and high noise, where the content of the image is decided.

So, honestly: L_simple is motivated by the ELBO but is not equal to it. If you need likelihoods (bits per dimension), you must use the weighted bound or a learned variance (Nichol & Dhariwal 2021).

A4 · three targets, one rotation

$x_t$ and $v$ are $x_0$ and $\epsilon$ rotated by an angle that grows with t

$$x_t = \cos\phi\,x_0 + \sin\phi\,\epsilon$$
$$v = \cos\phi\,\epsilon - \sin\phi\,x_0$$
$$x_0 = \cos\phi\,x_t - \sin\phi\,v, \quad \epsilon = \sin\phi\,x_t + \cos\phi\,v$$

Given $x_t$, predicting any one of $\epsilon$, $x_0$, $v$ determines the others; the sampler must use the matching conversion.

computed

Since ᾱ + (1 − ᾱ) = 1, write √ᾱ = cos φ and √(1 − ᾱ) = sin φ: x_t is a rotation of (x₀, ε).

v is the perpendicular direction; inverting the rotation recovers x₀ and ε (Salimans & Ho 2022).

A8 · flow matching

Learn a velocity along straight lines from noise to data

$$x_\tau = (1-\tau)\,x_{\text{noise}} + \tau\,x_{\text{data}}$$
$$u = x_{\text{data}} - x_{\text{noise}}$$
$\min_\theta\ \mathbb E\,\|v_\theta(x_\tau, \tau) - u\|^2$,   then integrate $\dfrac{dx}{d\tau} = v_\theta$

Where straight lines cross, the network can only learn their average direction, so the learned paths curve.

computed

A9 · the masked-diffusion objective and sampler

LLaDA's loss and its low-confidence remasking

$$\mathcal L(\theta) = -\,\mathbb E_{t, x_0, x_t}\Big[\dfrac{1}{t}\sum_{i=1}^{L}\mathbf 1[x_t^i = \texttt{MASK}]\,\log p_\theta(x_0^i\mid x_t)\Big]$$

$t\sim U(0, 1]$: each token masked independently with probability $t$

  1. Choose a response length and a number of steps; mask every response slot.
  2. Each step: predict all masked slots in one pass.
  3. Keep the most confident predictions (the schedule says how many); re-mask the rest.
  4. Prompt tokens are never masked during fine-tuning or generation.

Nie et al., Large Language Diffusion Models (LLaDA), 2025.

The 1/t weight makes this an upper bound on the negative log-likelihood. Without it, it is an ordinary masked cross-entropy, a different objective.
