Use memory to filter a changing gradient direction

In this computed ravine, one coordinate is one hundred times steeper. Plain gradient directions swing across the valley. Momentum blends successive gradients before moving.

Actual Lecture 5 example L(q) = 0.5 q₁² + 50 q₂² gₜ = (qₜ,₁, 100qₜ,₂) mₜ₊₁ = .8mₜ + .2gₜ qₜ₊₁ = qₜ − .095mₜ₊₁

Same direction: build speed

Plain GD uses only today’s gradient, so its step shrinks as the remaining error shrinks. Momentum keeps part of earlier, agreeing gradients—like repeated pushes in the same direction.

actual q₁ moves: GD +.0456 → +.0447 · momentum +.0456 → +.0812

Direction reverses: brake the zigzag

Across the valley the gradient flips sign. Old and new contributions oppose each other, so the stored direction becomes much smaller.

actual update 2 across q₂: plain GD +1.454 · momentum +.162

The rates here are matched so both methods make the same first move. The rolling-ball picture is an intuition for accumulated direction, not a literal force law or a guarantee that every momentum step lowers the loss.

Before the first gradient q₀ = (−2.4, .85) · m₀ = (0, 0) m means gradient memory. We start it at zero because no earlier gradient exists—not because the current gradient is zero.

The first two updates, without skipping a line

The first update creates memory. The second shows what cancellation means numerically.

Update 1 · start from m₀ = (0, 0)

g₀ = (−2.4, 85)

m₁ = .8(0, 0) + .2(−2.4, 85) = (−.48, 17)

q₁ = (−2.4, .85) − .095(−.48, 17) = (−2.3544, −.765)

Update 2 · remeasure at q₁

g₁ = (−2.3544, −76.5)

m₂ = .8(−.48, 17) + .2(−2.3544, −76.5) = (−.85488, −1.7)

q₂ = (−2.3544, −.765) − .095(−.85488, −1.7) = (−2.2732, −.6035)

Along the valley: the q₁ gradients stay negative, so their memory reinforces. Across the valley: .8(17) = 13.6 and .2(−76.5) = −15.3 partly cancel, leaving m₂,₂ = −1.7 rather than another large swing.
